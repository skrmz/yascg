### JSON artifact contract

| Concern | Rule |
| --- | --- |
| Exchange | Toolkit `out/spell-short-descriptions.{en,de}.json` → application `src/data/spell-short-descriptions.{en,de}.json` → root URLs with the same filenames. Files are UTF-8 without a BOM, LF, two-space indentation, canonical ASCII ID keys sorted by code unit, fields ordered `description` then `higherLevels`, and one trailing newline. Preserve the exact decoded Markdown strings. |
| Shape and IDs | Each top-level object maps a unique ID matching `^srd-[a-z0-9]+(?:-[a-z0-9]+)*$` to a strict object with required `description` and optional `higherLevels`. Each present value is a nonblank string of at most 20,000 characters under the app's Zod string limit. Reject extra fields, arrays, nulls, unknown IDs and duplicate keys during import/tests. A present ID must exist in that locale's normalized dataset. Match by canonical ID, independent of titles, labels and ordering. |
| Locale and coverage | The filename carries the exact dataset locale. Check German set equality with its normalized dataset. Require English `srd-fireball` and permit missing English keys. Phase 5 separately asserts the migration has **exactly** one English key and the original hashes. For subsequent imports review additions and removals against the parent commit and require a documented reason for any removal. Extend the test policy explicitly when introducing another released sidecar locale. |
| Missing or invalid | The application validator rejects an absent released file, malformed asset or invalid entry before import. In the browser a failed fetch, non-JSON response or bad top-level object yields an empty map, and invalid entries are skipped. Entries absent from the selected locale yield the localized unavailable state, including unsupported locales. The browser uses the existing safe Markdown renderer. |
| Source freshness and provenance | The toolkit computes SHA-256 over JSON containing normalized `description` and `higherLevels ?? []` for that locale, exactly as today. The transform excludes stale, withheld, orphaned and non-shortening entries. Review decisions bind to source and candidate hashes. Retain those hashes in authoring and record the input app commit/hashes and output hashes in toolkit provenance. Sidecars carry zero provenance fields. Apps cannot infer semantic freshness from this shape. For source edits, compare normalized descriptions/scaling by locale and ID, refresh toolkit inputs and revalidate affected sidecar entries before importing. Review changes to contextual mechanics or catalog inputs too, since those do not affect the current source hash. |
| Compatibility | The app schema is the compatibility authority. Coordinate changes to filenames, canonical IDs, field rules or limits with the toolkit contract and fixtures before importing new output. Keep the current payload shape and omit an envelope or schema version for this migration. |

**Acceptance gate.** Normal app tests reject incompatible sidecars without the generator. SRD normalization remains deterministic, and the toolkit still owns artifact reproduction and semantic freshness.
