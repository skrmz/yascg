# Implementation Plan — Spell Short Descriptions (Stage A)

- **Source of truth:** `.kilo/plans/1794345181476-spell-short-descriptions-spec.md` (the "SPEC").
- **Scope:** Stage A implementation only: schemas, deterministic transform, runtime loading, editor action, authoring CLI with injected/mocked provider, drift and security tests, documentation.
- **Explicitly out of scope for the coding agent:** live OpenRouter calls, credential access, production content generation, Stage B seed authoring, Stage C full generation. These are user-operated handoff steps.
- **Precondition:** The SPEC must be explicitly approved by the user before implementation starts. Then materialize it verbatim at `docs/changes/spell-short-descriptions/SPEC.md`. Do not delete or overwrite `CR.md` or `DECISIONS.md`.

Normative behavior lives in the SPEC. This plan fixes module boundaries, file paths, sequencing, and verification. Where the SPEC grants implementation discretion, the choice is recorded under "Resolved choices".

---

## 1. Guardrails

- Do not import `scripts/short-descriptions/**` into `src/` application code, `index.html`, or `vite.config.ts`. The only shared code is `src/domain/short-descriptions.ts` (pure schemas/types).
- No file under `src/` may reference `OPENROUTER_API_KEY` or `VITE_OPENROUTER`.
- `scripts/short-descriptions/build.ts`, `validate.ts`, and all transform modules must run with `OPENROUTER_API_KEY` unset and must perform no network calls.
- Do not add dependencies. Use `node:util.parseArgs`, `node:fs/promises`, `node:crypto`, and built-in `fetch`.
- Do not modify `src/data/spells.srd*.json`, `spell-languages.json`, SRD raw data, Dexie schemas, custom-spell payloads, deck payloads, or rendering/fit/print code.
- Do not read, search, or modify `docs/archive/`.
- Do not run `pnpm run build` casually during exploration: it rewrites `src/data` from `data/srd`. Run it only for verification after changes.
- Stage A must not fabricate production short-description content. The seed content in Stage B is generated by the user through the real pipeline.

## 2. Resolved implementation choices

| Decision | Choice |
|---|---|
| Shared runtime schema | `src/domain/short-descriptions.ts`: canonical ID pattern, runtime entry schema, shared limits/types. No Node imports. |
| Pure tooling | `src/tools/short-descriptions/`: authoring schema, Markdown safety, numeric/dice normalization, material-shortening rule, pure sidecar transform, deterministic serialization. No Node, network, or secrets. Not imported by the app. |
| Node/authoring boundary | `scripts/short-descriptions/`: filesystem I/O, SHA-256 fingerprints, atomic writes, OpenRouter adapter, prompts, report, CLIs. |
| Tooling test placement | Extend Vitest `test.include` to include `scripts/**/*.test.ts`; remove `scripts/**` from `test.exclude`. Pure tooling tests live under `src/tools/short-descriptions/*.test.ts`. Add `// @vitest-environment node` to filesystem/CLI tests. |
| Fingerprint location | `scripts/short-descriptions/fingerprint.ts` using `node:crypto`. The pure transform accepts precomputed fingerprints, keeping it environment-free and testable. |
| Locale list | Read from the generated `src/data/spell-languages.json` at transform/validation time. Never hard-code or extend it. |
| CLI parser | `node:util.parseArgs`. Flags and behaviors follow SPEC §8. |
| Default models | A documented shared default constant in the adapter; overridable via `OPENROUTER_MODEL` / `OPENROUTER_JUDGE_MODEL` and `--model` / `--judge-model`. |
| Material shortening | Candidate field is materially shorter when `candidate.length <= source.length * 0.9`; source field text is array items joined with `\n\n`. One replaced field is enough for runtime eligibility. |
| Authoring files in Stage A | Commit empty `data/short-descriptions/en.json` and `de.json` plus `{}` sidecars for every manifest locale, so the transform and drift gate have a stable baseline. |
| Report | `data/reference/short-description-review.json`; optional to commit; never a build input or drift input. |

### Task 5 — Pure authoring tooling

Create `src/tools/short-descriptions/` with no Node, filesystem, network, or credentials.

**`authoring-schema.ts`**

- Strict authoring file schema:
  - `locale`: non-empty string; caller validates it against the filename and manifest.
  - `entries`: array.
  - Entry: strict object with `spellId`, `description`, optional `higherLevels`, `sourceHash`, `status`, `acceptance`, `origin`.
  - `status`: `accepted | withheld` only. No `invalid`.
  - `acceptance`: `auto | human`.
  - `origin`: `generated | manual`.
  - `spellId`: canonical pattern; malformed IDs fail schema.
  - `sourceHash`: `/^sha256:[0-9a-f]{64}$/`.
  - Non-empty description, length limits, combined description + higher-level limit.
  - Safe Markdown refinement via `markdown-safety.ts`.
  - Duplicate `spellId` values fail the schema.
- Before validation, normalize whitespace-only `higherLevels` to omitted; do not otherwise trim stored text.
- Provide a helper to sort entries by `spellId` when writing authoring files.

**`markdown-safety.ts`**

- Use `marked` (already a dependency) or the app parser token walker.
- Reject raw HTML, links, images, URLs, scripts, and constructs not allowed by SPEC §9.1.
- Allow paragraphs, headings, lists, blockquotes, bold/italic, and code where the app renders them.
- Return structured findings naming the offending construct.
- Unit tests for allowed and rejected constructs.

**`normalize.ts`**

- Implement the bounded TOOL-17 extraction and comparison:
  - Dice (`NdS`, `NS`, `WS`, `dS`, locale variants, modifiers).
  - Quantities with units and locale number words/fractions.
  - Explicit conversion constants: time (`1 minute = 10 rounds = 60 seconds`, `1 hour = 60 minutes`, `1 round = 6 seconds`, `1 day = 24 hours`), distance/area (`5 feet = 1.5 meters` as a labeled approximation), weight.
  - Formatting-insensitive normalization (separators, zeros, dashes, decimal commas).
  - Classification: `equivalent`, `mismatch`, `unresolved`.
- Do not build a general NLP/rules engine. Every table entry is a literal equivalence.
- Unit tests must include the SPEC §14 minimum cases and every table addition.

**`material-shortening.ts`**

- `joinField(items)` = items joined with `\n\n`.
- `isMateriallyShorter(candidate, source, threshold = 0.9)`.
- `isRuntimeEligible(entry, source)` returns true if at least one replaced field is materially shorter.
- Shared by generation, validation, and transform.

**`transform.ts`**

- Pure `buildRuntimeSidecars(input)`:
  - Inputs: manifest locales, authoring files per locale, normalized datasets per locale, current fingerprints per locale, and the material-shortening rule.
  - Validate structure and locale/file agreement.
  - Filter: `status === "accepted"`, matching fingerprint, known dataset ID, and runtime-eligible.
  - Unknown/orphaned IDs, stale entries, withheld entries, and non-shortening entries become warnings, not failures.
  - Emit one sorted sidecar per manifest locale; `{}` when empty.
  - Return `{ files, warnings, diagnostics }`; do not write files.
- No semantic validation, severity scoring, or model call.

**`serialize.ts`**

- Sort top-level keys.
- `JSON.stringify(value, null, 2) + "\n"`.
- LF only; no platform newline conversion.
- Preserve entry key order `description`, then optional `higherLevels`.

**Tests under `src/tools/short-descriptions/*.test.ts`**

- Authoring schema: valid, malformed, missing/extra fields, empty text, limits, duplicates, malformed IDs, unknown-but-well-formed IDs passing schema, unsafe Markdown rejection, no `invalid` status.
- Fingerprint-independent transform: fresh/stale/withheld/unknown/non-shortening handling; deterministic serialization; metadata exclusion; one sidecar per locale; `{}` fallback; unknown IDs omitted with warnings; schema violations fail.
- Material shortening: both fields, one field, neither, omitted higher levels.
- Normalization: all required equivalence, mismatch, and unresolved cases.

### Task 6 — Authoring CLI and OpenRouter adapter

Create `scripts/short-descriptions/`.

**`fingerprint.ts`**

- `sourceFingerprint(spell)` = SHA-256 over UTF-8 `JSON.stringify({ description, higherLevels: higherLevels ?? [] })`, formatted `sha256:<64 hex>`.
- Deterministic across runs and independent of JSON file formatting.
- Tests: changes with description/higherLevels; ignores name and metadata.

**`files.ts`**

- Resolve repository root from `import.meta.url`.
- Paths:
  - `data/short-descriptions/<locale>.json`
  - `src/data/spell-languages.json`
  - `src/data/spells.srd*.json`
  - `src/data/spell-short-descriptions.<locale>.json`
  - `data/reference/short-description-review.json`
- JSON read helpers with actionable diagnostics naming file and `spellId`/field.
- Atomic write helper: write a temp file in the destination directory, then rename over the target. Never truncate the target first.
- Staging directory under `os.tmpdir()` for smoke runs.

**`cli.ts`**

- Parse flags with `node:util.parseArgs`.
- Resolve generation and judge models: flag > environment variable > shared documented default.
- Resolve `OPENROUTER_BASE_URL` and `OPENROUTER_API_KEY` only when a model call is needed.
- Shared output helpers for warnings, failures, and exit codes `0 | 1 | 2`.
- Never echo the key; redact `Authorization` and key-like strings from errors.

**`prompt.ts`**

- Generation prompt:
  - Locale, public SRD source text and relevant public metadata, abbreviation catalog shorts, content conventions, and required JSON shape.
  - Explicit instruction to preserve all mechanics and put scaling in `higherLevels`.
  - No user data.
- Judge prompt:
  - Source and candidate text, deterministic unresolved items as required review items, severity rubric, required JSON shape.
  - Explicit instruction not to rewrite text.
- Keep prompts out of reports and logs.

**`openrouter.ts`**

- Built-in `fetch` only; injectable `fetchImpl` for tests.
- `generateCandidate` and `compareCandidate` methods; independent generation/judge models.
- Request JSON-schema structured output and `max_tokens`.
- Timeouts (default 120s) and bounded retries (default 3) with exponential backoff and jitter for 429, 5xx, and transient network errors. No retry for 400/401/403/422 or invalid output.
- Validate every response locally with Zod.
- Surface distinguishing diagnostics for missing credentials, 401/403, 404/model unavailable, 400/422 response-format rejection, schema-invalid output, rate limiting, server error, and timeout.
- `/models` pricing lookup once per run when `--max-cost` is set; report `unavailable` rather than inventing prices.
- Accumulate per-entry and per-run usage from `usage`; estimate cost only when pricing was retrieved.
- Abort before the next call when projected cost would exceed `--max-cost`.

**`checks.ts`**

- Orchestrate deterministic checks from the pure modules:
  - structural/schema (already enforced by authoring schema),
  - Markdown safety,
  - dice/quantity normalization,
  - rules vocabulary,
  - scaling and higher-level consistency,
  - length/material shortening,
  - content integrity,
  - provenance fingerprint.
- Produce findings with category, severity, evidence, and recommended action.
- Classify `accepted` vs `withheld` according to SPEC §9.2.
- Rejected-before-write candidates get report outcome `invalid`; they are never written.
- Never treat `unresolved` as accepted without judge clearance.

**`report.ts`**

- Build the report at `data/reference/short-description-review.json`.
- Include timestamp, provider, generation/judge models, base URL (never key), run outcome, exit code, counts by locale/status/acceptance, automatic-acceptance ratio, per-entry findings, usage/cost or `unavailable`, and failures/skips.
- Redact prompts, headers, keys, custom spells, decks, and other user data.
- Atomic write.

**`generate.ts`**

- Selection:
  - Default: missing + stale entries.
  - `--ids`, `--limit`, `--locale`, `--all`, `--regenerate`, `--approve`, `--force`.
  - Refuse when computed selection exceeds `--max-entries` (default 25) without `--ids` or `--limit`.
- `--dry-run`: selection and deterministic validation only; no pricing lookup, model call, or writes.
- `--approve`: deterministic validation only; set `acceptance: human`, `status: accepted`, update fingerprint; optional `--manual` sets `origin: manual`; never accepts schema violations.
- `--regenerate`: skip `acceptance: human` and `origin: manual` unless `--force`.
- Per-entry pipeline: prompt → generation call → schema validation + `spellId` match → deterministic checks → semantic comparison → severity → staging. No writes until all processing completes.
- Stale revalidation follows TOOL-5 exactly: accepted stays accepted without blocking findings; withheld never auto-promotes; blocking findings withhold; text is never rewritten.
- Commit order: report temp + authoring temp files, rename authoring files, rename report.
- Exit codes: `0` complete (including all withheld), `1` structural/fatal with no writes, `2` partial success with at least one committed and one failed.
- Never claim cross-file atomicity; state partial success explicitly in stdout and the report.

**`validate.ts`**

- Load authoring files, datasets, manifest, and compute fingerprints.
- Run deterministic/report checks, including coverage, stale, withheld, unknown/orphaned, duplicate, malformed, higher-level incompleteness, non-shortening, and runtime drift.
- Write the report atomically. No model calls, no key required.
- Exit `0` for non-fatal warnings; `1` for structural/fatal errors.

**`build.ts`**

- Read authoring files, manifest, and normalized datasets.
- Compute fingerprints.
- Call the pure transform.
- Write sidecars atomically.
- Print warnings for omitted entries.
- Fail only on structural errors and genuine write/processing failures.
- No OpenRouter import, no network, no key.

**`smoke.ts`**

- Manual-only.
- Require `--ids`; cap at 3; refuse `--all`.
- Default stage results in `os.tmpdir()`, outside tracked paths; `--write` is the explicit seed-batch operation.
- Run the complete pipeline: generation, local schema validation, deterministic checks, semantic comparison, severity classification, staged report, pure transform, runtime-schema validation of transformed output.
- Print model, request mode, per-step pass/fail, token usage/cost or `unavailable`, and distinguishing diagnostics.
- Refuse without credentials before any network call.

**Tests under `scripts/short-descriptions/*.test.ts`**

- Adapter: mock fetch; URL/headers/body; model precedence; missing-key error before fetch; key absent from errors/logs/report; retries/timeouts; 401/403 no retry; 429/5xx retry; invalid JSON/schema; usage/cost or `unavailable`.
- Cost protection: selection refusal; `--all` requirement; budget abort; partial-success exit code; pricing unavailable behavior.
- Write semantics: simulated write/rename failure leaves target byte-identical or fully replaced; partial batch exit 2; report rename failure after authoring commit reports the accurate state; total failure leaves files unchanged.
- Stale revalidation transitions.
- Approve/regenerate/force protection.
- `--dry-run` makes no calls, no pricing lookup, no writes.
- Exit codes for complete, structural failure, and partial success.
- Smoke: no credentials; missing `--ids`; `--all` refusal; staging outside tracked paths; not wired into build/test/preview/deploy; mocked diagnostics.
- Security separation:
  - No `OPENROUTER_API_KEY`/`VITE_OPENROUTER` in `src/`, `index.html`, or `vite.config.ts`.
  - No app import of `scripts/short-descriptions/openrouter.ts`, `generate.ts`, or `smoke.ts`.
  - `vite.config.ts` and `index.html` do not reference the generator.
  - Transform/validation path with an injected throwing fetch performs no network call.

### Task 7 — Drift test

**New: `src/test/short-descriptions-drift.test.ts`**

Use the same Git-object-store approach as `src/test/srd-dataset.test.ts`.

- Inputs:
  - Authoring: `git show HEAD:data/short-descriptions/<locale>.json` and working tree.
  - Datasets: `git show HEAD:src/data/spells.srd*.json` and working tree.
  - Sidecars: `git show HEAD:src/data/spell-short-descriptions.<locale>.json` and working tree.
  - Transform code: always the working-tree implementation.
- Assertion A:
  - Compute expected sidecars from HEAD authoring + HEAD datasets + HEAD fingerprints.
  - Compare raw bytes with HEAD sidecars.
  - Missing HEAD authoring means an empty authoring set; missing HEAD sidecar fails with a message that sidecars are not committed yet.
- Assertion B:
  - Compute from working-tree authoring + working-tree datasets.
  - Compare raw bytes with working-tree sidecars.
  - Failure message names `pnpm run short-descriptions:build`.
- Both assertions also check:
  - sorted keys, 2-space JSON, LF, trailing newline;
  - no `sourceHash`, status, acceptance, origin, review, timestamp, or model metadata;
  - no `sk-or-` key material.
- Neither assertion invokes the generator, requires `OPENROUTER_API_KEY`, or performs network calls.
- Missing Git, non-repository checkout, or unavailable object is a hard failure with an explanatory message.

A transform-code change without regenerated sidecars must be detected because the transform is the working-tree implementation in both assertions.

## 4. Runtime flow summary

1. App startup loads manifest, English dataset, selected-language dataset, and the selected-language sidecar.
2. Sidecar failures are isolated; the editor still works and the action is disabled.
3. User adds an active-deck SRD spell and chooses Create editable copy.
4. `DetailsPane` passes the captured `sourceSpellId` to `CustomSpellForm`.
5. `CustomSpellForm` captures `session.language` and looks up the candidate in that locale’s map.
6. Apply replaces `description` and optionally `higherLevels`, pushes one tagged undo snapshot, and shows a localized status.
7. Save uses the existing custom-spell path; no new persistence or provenance.
8. Reopening the saved copy has no origin ID and therefore no apply action.

## 5. Authoring flow summary

1. `short-descriptions:generate` selects missing and stale entries, bounded by flags.
2. It calls OpenRouter through the local adapter and validates the returned JSON locally.
3. Deterministic checks and the semantic comparison classify findings.
4. The authoring file is updated in memory, then written atomically per file; failed entries keep their previous content.
5. `short-descriptions:build` recomputes fingerprints and emits deterministic sidecars.
6. `short-descriptions:validate` writes the review report and exits with the documented code.
7. The user commits authoring files, sidecars, and optionally the report.
8. The drift test verifies both committed and working-tree consistency.

## 9. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Vitest currently excludes `scripts/**`, so tooling tests would silently not run. | Task 1 extends `test.include`; verify with a deliberately failing temporary assertion or `vp test --reporter=verbose` during development. |
| App accidentally imports the OpenRouter adapter. | Security separation test scans `src/`, `index.html`, and `vite.config.ts`; adapter stays under `scripts/`. |
| Drift test becomes a false negative after a local build. | Assertion A uses `git show HEAD:` for authoring, datasets, and sidecars. |
| Sidecar loader breaks startup when a file is missing. | Non-throwing loader returns an empty/partial map; provider loads it in isolation. |
| Atomic write on Windows behaves differently. | Use same-directory temp + `rename`; tests simulate write/rename failure and compare old/new bytes. |
| Tooling tests import Node built-ins under jsdom. | Add `// @vitest-environment node` to filesystem/CLI test files. |
| Applying short text clears `higherLevels` unintentionally. | Entry-omitted `higherLevels` preserves the draft value; explicit tests. |
| Undo labels regress existing abbreviation tests. | Keep `form.abbreviate.undo` whenever the top action is not `shortDescription` or the stack is empty. |
| Report leaks prompts or keys. | Central redaction helper; tests assert absence of key/prompt/header fields. |
